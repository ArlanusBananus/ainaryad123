---

## 🌟 О проекте

«НарядAI» — это мобильно-веб система с искусственным интеллектом, автоматизирующая полный цикл управления ремонтными и плановыми нарядами горно-обогатительного предприятия. Мастер смены выдаёт наряды за **1 минуту / 6 кликов**, исполнители работают через мобильный PWA-интерфейс с крупными кнопками (удобно в рабочих перчатках), а ИИ выступает **цифровым контролёром смены**: следит за сроками, проверяет качество закрытия нарядов, сверяет фото «до» и «после», находит аномалии оборудования и формирует объективный рейтинг бригад.

## ⚡ Быстрый запуск

### 1. Запуск бэкенда (Python FastAPI)

```bash
cd backend

# Установка зависимостей
python -m pip install -r requirements.txt

# Запуск сервера API на порту 8000
python run.py
```
> Бэкенд запустится на `http://localhost:8000`. При первом старте база данных SQLite (`naryad.db`) создаётся и автоматически наполняется тестовыми данными по Разделу 8 ТЗ.  
> Документация Swagger UI доступна по адресу: `http://localhost:8000/docs`.

### 2. Запуск фронтенда (React + Vite)

В отдельном окне терминала:
```bash
cd frontend

# Установка пакетов (если еще не установлены)
npm install

# Запуск dev-сервера
npm run dev
```
> Приложение откроется на `http://localhost:5173`.  
> Все запросы `/api`, `/uploads` и `/ws` автоматически проксируются на бэкенд.

## 🔄 10 статусов жизненного цикла наряда (Раздел 4 ТЗ)

| № | Статус в системе | Отображение в UI | Описание перехода |
|---|---|---|---|
| 1 | `ISSUED` | **Выдан** | Мастер выдал наряд с телефона (push исполнителю) |
| 2 | `ACCEPTED` | **Принят в работу** | Исполнитель подтвердил приём задачи |
| 3 | `QUEUED` | **В очереди** | Наряд поставлен в очередь за текущим |
| 4 | `IN_PROGRESS` | **В работе** | Начато фактическое выполнение работ (фиксация времени) |
| 5 | `SUSPENDED` | **Приостановлен** | Ожидание запчастей / остановки агрегата (с указанием причины) |
| 6 | `REJECTED` | **Отклонён** | Отклонение с обоснованной причиной (перенаправление мастеру) |
| 7 | `EXECUTED` | **Исполнено** | Работы завершены, приложены материалы, шифр и фото «после» |
| 8 | `AI_CHECK` | **Проверка ИИ** | Цифровой контролёр оценивает полноту, логику списания и фото |
| 9 | `REWORK` | **На доработку** | Вердикт ИИ при отсутствии фото / лишних материалах (возврат в работу) |
| 10 | `CLOSED` | **Закрыт** | Мастер утвердил выполнение и оценку (финальное решение человека) |

## 🤖 Реализованные модули ИИ (Раздел 6 ТЗ)

1. **ИИ-контроль сроков (Раздел 6.1):**
   - Отслеживание дедлайнов в реальном времени.
   - За 30 минут до срока — предупреждение исполнителя.
   - Контроль непринятых нарядов (эскалация аварийных нарядов мастеру через 3 минуты).
   - Вывод сообщений об опоздании («Наряд №... просрочен на X мин»).
2. **ИИ-проверка выполнения наряда (Раздел 6.2):**
   - Проверка обязательности фото «после» для внеплановых работ (без фото наряд бракуется).
   - Проверка логичности списания ТМЦ (выявление завышенных объёмов и несовместимых запчастей).
   - Сравнение фактического времени со справочным нормативом.
   - Оценка от 1 до 100 баллов и текстовый отчёт с пояснением.
3. **ИИ-подбор лучшего исполнителя (Раздел 5.1 & 6.3):**
   - Анализ текста неисправности и типа оборудования.
   - Подбор свободных сотрудников профильной специальности (`FREE`) с максимальным рейтингом.
4. **ИИ-аналитика аномалий оборудования (Раздел 6.5 & 8):**
   - **Конвейер К-3:** выявление 7 поломок за 30 дней (из них 5 — шифр М-02). Рекомендация проверки соосности привода вала и включения в план ППР.
   - **Дробилка КМД-1750:** выявление превышения среднего времени простоя на 42% из-за заклинивания конуса.
5. **Рейтинг исполнителей и бригад (Раздел 6.6):**
   - Формула расчёта на основе качества ИИ, соблюдения сроков и доли нарядов без доработок.

## 📱 Сценарий демонстрации на защите (Раздел 11 ТЗ)

1. **Обзор смены мастером:** На верхнем переключателе выбран «Экран Мастера». Видны 5 счётчиков смены, статусы рабочих (зелёный/жёлтый/синий/серый) и Канбан-доска.
2. **Выдача наряда за 6 кликов:** Нажатие «ВЫДАТЬ НАРЯД» -> Участок -> Оборудование -> Шаблон поломки (течь масла насоса) -> ИИ автоматически предлагает свободного слесаря (Ахметов Е.) -> Нажатие «ВЫДАТЬ НАРЯД».
3. **Реакция исполнителя:** Переключение на «Экран Исполнителя». Срабатывает тревога, карточка мигает красным. Нажатие «Принять в работу» -> «Начать исполнение». На канбан-доске мастера статус меняется мгновенно по WebSocket!
4. **Сдача наряда с проверкой ИИ:** Нажатие «Исполнено» -> выбор шифра неисправности (Г-01), списание сальника и масла, прикрепление фото «после» -> «Отправить на проверку ИИ». ИИ выставляет вердикт «Принято» (94 балла).
5. **Тест отбраковки ИИ (пункт 7 сценария):** Сдача наряда без фото или с аномальным количеством подшипников (60 шт.) -> ИИ ставит вердикт «ТРЕБУЕТ ДОРАБОТКИ!» с аргументированным объяснением.
6. **Аналитика за 3 месяца:** Вкладка «Аналитика ИИ» на экране мастера показывает закономерности по Конвейеру К-3, Дробилке КМД-1750 и рейтинговую таблицу рабочих.
